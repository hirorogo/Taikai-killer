# 実行環境前提 — 通常マシン・サンドボックス無効（隔離なし）

Taikai-killer ハーネスの **実行環境に関する設計前提** を定義する。
パイプライン全体（README 1〜6 セッション）の運用に先立つ大前提であり、権限・隔離・ホスト選定の判断はここに従う。

> 更新（2026-06-11 ヒアリング確定）: 当初の「使い捨てホスト＋マシン破壊前提」は**撤回**。**通常マシンでサンドボックス無効のまま回す**（隔離なし・リスク受容）。

---

## TL;DR（結論）

1. **サンドボックスは無効で実行する。** エージェントはホスト上でフル権限（シェル・ネットワーク・ファイル・コード実行）を持つ。隔離・権限プロンプト・許可リストによる摩擦を設けない。
2. **通常マシンで動かす。専用の使い捨てホストは用意しない。** 破壊前提の犠牲ホストには依存せず、開発／実行に使う普段のマシン上で回す。
3. **その結果のリスク（任意実行によるホスト汚染等）は許容して進める。** 安全のための隔離はしないという選択を明示的に受け入れる。

> 旧版は「隔離対象をプロセスからマシンへ引き上げる（破壊可能なホストで担保）」だったが、使い捨てホストを使わない方針になったため、**安全は隔離でなく『リスク受容＋運用ガード（CB・予算・レビューゲート）』で担保**する。

---

## なぜサンドボックスを無効にするか

README が要求する動作特性は、サンドボックス前提と本質的に相性が悪い：

| README の要件 | サンドボックスとの衝突 |
|---|---|
| レートリミットの続く限り**無限でおこなう** | 権限プロンプト・隔離オーバーヘッドが無限ループの律速になる |
| **マルチエージェント・オーケストレーション**で並行実装 | 並列エージェントごとの隔離はコスト・複雑性が爆発する |
| 外部知見を**大量クロール**（Scrapling / playwright） | ブラウザ起動・任意ネットワークアクセスが隔離下で頻繁に弾かれる |
| **コード生成→実行→テスト**を通すまで続ける | 未知コードの実行が前提。サンドボックス内 false negative で「動いたつもり」が混入する |
| **止まったら自動で叩く / ratelimit復帰で再開** | 無人・無確認で進む前提なので、対話的な権限承認を挟めない |

→ 速度・自律性・再現性（実機と同条件での実行）を優先し、隔離は設けない。

## 受容するリスク（明示的に飲む）

通常マシン上でフル権限実行するため、以下を「想定内・許容済み」とする。発生しても**警告・確認・停止の対象としない**：

- 生成・取得したコード／スクリプトの**任意実行**によるホスト汚染・改変
- クロール対象への**大量アクセス**、認証試行、**使い捨て/テスト用**認証情報のホスト上での露出
- ファイルシステムの破壊的変更、パッケージ汚染、設定の上書き

> **二分線（重要）**: 受容するのは **①ホスト内の副作用** と **②使い捨て/テスト用の認証情報** だけ。
> **本番認証情報・外部への副作用（publish・送信・課金）は受容対象外**＝そもそも同一マシンに置かない／冪等化＋レビューゲート対象。
> 「警告・確認・停止しない」のは①②に限る。

> 使い捨てホストを使わない＝**マシンが壊れたら本当に困る**ので、旧版より「品質ガード」の比重が上がる。下記の運用ガードで暴走の実害を抑える。

---

## 安全の担保（隔離の代わりに運用ガード）

隔離しない代わりに、暴走の実害を以下で抑える：

- **Circuit Breaker**（連続失敗5 / 総リトライ20 / 連続空出力3 → exit 65）で暴走ループを止める（D11）
- **コスト上限**（任意 `budget_usd`、超過で exit 64。サブスク運用なので従量課金はなし／D5）
- **ヒューマンレビューゲート**（非STOP・非同期承認、危険な不可逆操作は承認待ち／D6）
- **冪等キー**で外部送信・publish の二重実行を防ぐ（D10）
- **append-only イベントログ**で全操作を監査可能にする（D9）

---

## やってよい／注意

- 開発常用マシン上での実行は**許容**（本方針）。
- ただし**外部に副作用が漏れる操作（publish・外部送信・課金）だけは冪等化＋レビューゲート対象**にする（ホストの外は壊せないため）。
- 価値あるデータ・本番認証情報を**同一マシンに不用意に置かない**運用上の注意は残る（隔離していないため）。秘密は環境変数のみ、設定ファイルに書かない。

---

## パイプラインとの関係

- **オーケストレータ**は権限制御・隔離を実装しない。代わりに **resume / circuit-breaker / cost-tracker**（速度・暴走・コストの制御）に注力する（D11/D5/D9）。
- ヒューマンレビュー必須セッションの STOP は「安全のための隔離」でなく「要件/戦略の妥当性確認」のため。実行安全は運用ガードで担保する。
